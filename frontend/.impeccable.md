# Diagramik Design Guidelines

## Design Context

### Users

Software engineers and cloud architects who need to generate technical diagrams quickly from natural language. They use this in a focused, heads-down work context — similar to reaching for a terminal or IDE. They are comfortable in dark interfaces and value clarity and speed over aesthetics. The product is a personal/semi-private tool, not a commercial SaaS.

### Brand Personality

**Calm, clear, honest.** Diagramik is a quiet, competent tool. It doesn't shout. It doesn't market itself. It gets out of the way and produces results. The personality is that of a trusted colleague who knows their craft.

### Aesthetic Direction

- **Visual tone**: Dark-native, minimal, high-contrast, technical precision
- **References**: Linear (sharp type hierarchy, dark surface layers, purposeful color use) + Raycast (elegant negative space, subtle depth, premium micro-interactions)
- **Anti-references**: Generic SaaS (gradients-as-decoration, rounded blob illustrations, hero sections) and corporate tools (heavy strokes, cramped density, Microsoft/Confluence aesthetic)
- **Theme**: Dark mode only

### Design Principles

1. **Clarity over cleverness** — Every element should earn its place. If it doesn't help the user understand or act, remove it.

1. **Surface calm, not noise** — Color is used sparingly and functionally: one accent (blue), semantic states (red/green/yellow), and neutrals. No decorative color.

1. **Developer-grade precision** — Typography is set with intention. Spacing is consistent. Alignment is exact. The UI should feel like it was built by someone who cares about craft.

1. **Honest feedback** — States (loading, error, success, empty) are communicated plainly and immediately. No spinner tricks to hide latency. No vague error messages.

1. **WCAG AA accessibility** — 4.5:1 contrast minimum for text, keyboard navigation throughout, aria-labels on all icon-only controls, aria-live for dynamic content changes, reduced-motion respect.

## Tech Constraints

- Tailwind CSS (extend the config to add design tokens rather than inlining every value)
- Vue 3 + Astro 5
- Heroicons v2 (outline style)
- No external component library — build composable Vue components
- System font stack (Inter or Geist could be added if needed)
